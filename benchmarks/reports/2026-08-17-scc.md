# Preliminary SCC benchmark report

This report is exploratory and is not a longitudinal baseline.

## Configuration

The benchmark ran on 2026-08-17 on an Apple M2 MacBook Air with four performance cores, four efficiency cores, and 24 GB of memory.

The operating system was Darwin 25.5.0 on `aarch64`.

The compiler was `rustc 1.95.0 (59807616e 2026-04-14)`.

The build used the workspace release profile, including LTO and one codegen unit.

The base revision was `78e6f1ea78dad1798dc7d09cd034cf201bda1845`.

The working tree contained the uncommitted benchmark project, so the revision alone does not identify the tested source.

Each point used one timely worker, seed `3237998146`, two warmup runs, and five measured runs.

Each graph contained twice as many generated edges as nodes.

Both compiled implementations used the node identifier to select the same logarithmic label-introduction round as DDIR's `enter_at($1[0])`.

The reported times are medians of `measured_ns` across the five runs.

The [raw JSONL records](2026-08-17-scc.jsonl) contain all 60 measured implementation runs.

## Absolute time

| Nodes | Edges | Output records | Compiled | Compiled DDIR plan | DDIR Vec | DDIR Corgi |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 2,000 | 1,291 | 11.880 ms | 12.253 ms | 43.701 ms | 40.468 ms |
| 10,000 | 20,000 | 12,782 | 69.385 ms | 74.685 ms | 299.581 ms | 247.720 ms |
| 100,000 | 200,000 | 126,361 | 0.780 s | 0.867 s | 4.054 s | 2.903 s |

## Ratios

| Nodes | Plan / optimized | Vec / plan | Corgi / Vec | Corgi / plan |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 1.031x | 3.567x | 0.926x | 3.303x |
| 10,000 | 1.076x | 4.011x | 0.827x | 3.317x |
| 100,000 | 1.113x | 4.674x | 0.716x | 3.346x |

The typed DDIR plan is 3% slower than optimized typed SCC at 1,000 nodes and 11% slower at 100,000 nodes.

This is the cost visible from using DDIR's generic operator plan instead of the specialized typed implementation.

Vec interpretation takes between 3.6 and 4.7 times the typed DDIR plan's time, with the ratio increasing across these three sizes.

Corgi improves relative to Vec as the graph grows, from 0.926x of Vec time at 1,000 nodes to 0.716x at 100,000 nodes.

Corgi remains between 3.3 and 3.4 times the typed DDIR plan at all three sizes.

## Correctness and variation

All four implementations produced identical consolidated weighted outputs at every scale.

The five 100,000-node runs had max-minus-min ranges of 3.80% of the median for compiled, 1.35% for the compiled DDIR plan, 1.43% for Vec, and 1.25% for Corgi.

The 10,000-node Vec and Corgi points had approximately 11% max-minus-min ranges, so their medians merit less confidence than the other points.

Stabilization accounted for at least 98.0% of measured time in every run.

This workload therefore says little about parsing, lowering, dataflow construction, or ingestion costs.

## Limits

The sweep used one seed, one edge density, one worker, and one input batch.

SCC structure depends on the graph generator, so these results should not be generalized to other graph families.

The timed stabilization phase includes capture of the full result but excludes output collection and correctness checking.

The result schema should record dirty-tree state or a source digest before it is used longitudinally.

Future reports should retain this shape: source and machine identity, workload parameters, correctness, absolute medians, ratios, variation, observations, and limits.
